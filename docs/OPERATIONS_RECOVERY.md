# ANGEL SUTDA 운영 · 백업/복구 · 장애 대응 Runbook

기준선: GAME CORE `STABLE_1` / GAME SECURITY `GAME_SECURITY_1`
이 문서의 모든 절차는 **기준선을 변경하지 않는다.** 카드/게임방/Realtime/RPC/베팅/정산/사이드팟/재경기 로직은
실제 재현된 버그가 있을 때만 "재현 → 원인 특정 → 최소 수정 → 회귀(2개 베이스라인 문서 전체)" 순서로 수정한다.

---

## 0. 장애 발생 시 최초 5분 (공통)

1. 관리자 콘솔 → **대시보드**: CRITICAL 건수, 정지 라운드, REALTIME, USDT WATCHER, 점검/게임잠금 상태 확인.
2. **서버 상태/무결성** 패널에서 `무결성 검사 실행` → OPEN finding 확인.
3. 영향 범위 판단
   - 게임 진행 불가 → 1번 · 2번 절차
   - 돈 관련(충전/출금/포인트) → 4번 · 5번 · 6번 절차
   - 전체 서비스 이상 → **시스템 설정 → 점검 모드 ON**(신규 판 시작 차단, 진행 중 판은 정상 종료)
4. 조치는 반드시 관리자 RPC로 수행한다(모든 처리가 `admin_logs`에 기록됨). DB 직접 UPDATE는 최후 수단이며
   사유를 `admin_logs`에 남긴다.

## 1. 백업 현황과 복구 절차

| 항목 | 방식 | 보존 | 복구 방법 |
| --- | --- | --- | --- |
| 데이터베이스 | Lovable Cloud 관리형 자동 백업(일 단위 스냅샷 + PITR) | 플랜 기준 보존 | 지원 채널로 복구 시점(UTC) 지정 요청 |
| 상점/상품 이미지 | `shop-assets` 프라이빗 버킷 | 삭제 시 수동 재업로드 | 관리자 → 상점 관리에서 재업로드 |
| 스키마/함수 | `supabase/migrations/*` (코드 저장소) | 영구 | 마이그레이션 재적용 |
| 애플리케이션 | 코드 저장소 + 배포 이력 | 영구 | 이전 배포로 롤백 후 재배포 |

복구 원칙
- **DB 전체 복원은 최후 수단.** 포인트/충전/출금 데이터는 원장(`point_transactions`)이 함께 이동해야 정합성이 유지된다.
- 부분 손상(특정 회원/방/라운드)은 복원이 아니라 관리자 RPC 보정으로 처리한다.
- 복원 후에는 반드시 8번 스모크 체크를 수행한다.

## 2. Runbook A — 라운드 정지 (STUCK ROUND)

증상: 대시보드 `정지 라운드 > 0`, 특정 방에서 턴이 넘어가지 않음.

1. 관리자 → **실시간 모니터링**에서 해당 방/라운드 확인.
2. 방 진행 로그(`방 진행 로그`)에서 마지막 액션과 `error_code` 확인.
3. 1차 조치: **턴 타임아웃 강제 진행**(자동 enforce). 5초 내 진행되지 않으면 2차.
4. 2차 조치: **방 관리 → SAFE CLOSE**(진행 중 라운드 정산 후 종료).
5. 3차 조치: SAFE CLOSE가 실패하면 **FORCE DELETE**. 이 경우 POT 보정이 필요할 수 있으므로 3번 절차로 이동.
6. 종료 후 `무결성 검사`로 POT/정산 finding 0 확인.

## 3. Runbook B — POT / 정산 불일치

1. **서버 상태/무결성 → 무결성 검사 실행**, `POT_MISMATCH` / `SETTLEMENT_PAYOUT_MISSING` 상세 확인.
2. 해당 라운드의 `game_actions` 합계와 `game_round_players.total_bet`, `carry_in/carry_out`을 비교한다.
   불변식: `pot = 모든 베팅 합계 + carry_in`, `delta = carry_in − carry_out`.
3. 원인이 테스트 데이터면 finding을 `테스트 이력(IGNORED_TEST)`으로 처리한다.
4. 실제 회원 손해가 확인되면 **포인트 지급/회수**에서 사유를 명시해 보정한다(감액이 아닌 부족분 지급 우선).
5. 처리 후 finding을 `해결(RESOLVED)`로 전환한다. finding은 삭제하지 않는다.

## 4. Runbook C — 포인트 오차 / 원장 이상

1. `POINT_MISMATCH` finding에서 대상 회원 확인.
2. **회원 관리 → 포인트 원장**에서 잔액 흐름을 확인해 어느 트랜잭션부터 어긋났는지 특정.
3. 잠금 포인트 이상은 `잠금 포인트 보정` RPC를 사용한다(출금 신청 중인 금액이 있는지 먼저 확인).
4. 보정은 항상 **관리자 RPC + 사유 필수**. 직접 `profiles.game_points` 수정 금지.
5. 정책 고정값 확인: 충전 수수료 7%(면제권 100% 면제), 총판 커미션 2%, 출금 수수료 0%.

## 5. Runbook D — USDT 자동충전 실패

증상: 대시보드 `USDT WATCHER = OFFLINE` 또는 `자동충전 지급 오류` 경고.

1. **USDT 자동충전** 패널에서 watcher 마지막 성공 시각, 실패 연속 횟수, 잠금 상태 확인.
2. `IDLE`이 아닌 상태로 10분 이상 고정 → watcher 잠금 해제 후 재실행.
3. 입금은 들어왔는데 미지급인 경우
   - `chain_deposits`에서 txid/금액/컨펌 확인
   - 신청 건의 `expected_usdt`와 실제 입금액 일치 여부 확인(6자리 고유값)
   - 일치하면 재확정 처리, 금액 불일치면 회원 안내 후 관리자 수동 충전 처리(사유 기록)
4. 회원이 만료된 신청에 입금한 경우: 신규 신청 생성 없이 관리자 수동 처리 + `admin_logs` 사유 기록.
5. 정책상 **환율 스냅샷은 신청 시점 값으로 고정**한다. 사후 환율로 재계산하지 않는다.

## 6. Runbook E — 출금 사고 대응

1. 이중 지급 의심 시 즉시 **점검 모드 ON + 출금 차단**.
2. `withdrawal_requests` + `withdrawal_request_logs`로 상태 전이(REVIEWING→APPROVED→PAID) 중복 확인.
3. 실제 이중 송금이면 회수는 포인트 회수로 처리하고 사유를 상세히 남긴다.
4. 출금 수수료는 0%로 고정. 정책 변경으로 대응하지 않는다.

## 7. Runbook F — 로그인/인증 장애, G — 실시간 끊김, H — 부정행위 신고, I — 관리자 권한 사고, J — 배포 롤백

- **F 인증**: `/auth` 오류 발생 시 소셜 제공자 상태 → 세션 만료 → 브라우저 저장소 순으로 확인. 회원 다수 영향 시 점검 모드 ON.
- **G 실시간**: `REALTIME` 경고 + 최근 15분 게임 오류 증가 → 진행 중 방은 SAFE CLOSE로 정리, 신규 판은 게임 잠금으로 차단.
- **H 부정행위**: 신고 접수 → 방 진행 로그/카드 무결성 검사 → 필요 시 정지/채팅금지. **상대 히든카드는 관리자도 조회하지 않는다**(보안 기준선).
- **I 권한 사고**: 최고관리자 계정에서 `관리자 계정` 패널로 권한 회수 → `운영 로그`로 해당 관리자의 전체 조작 이력 확인.
- **J 롤백**: 배포 이후 회귀 발생 시 이전 배포로 롤백. DB 마이그레이션이 포함된 배포는 **롤백 전 스키마 호환성 확인**(컬럼 추가는 안전, 삭제/변경은 별도 마이그레이션 필요).

## 8. 복구 후 스모크 체크 (필수)

1. `/` `/rooms` `/shop` `/ranking` `/wallet` `/admin` 정상 로드.
2. 로그인 2계정으로 방 생성 → READY → 2장 1판 정상 정산.
3. 3장 1판(OPEN/OPEN/PEEL → 최종 2장 제출) 정상 정산.
4. 대시보드 CRITICAL 0 · 정지 라운드 0 · OPEN finding 0.
5. USDT 신청 1건 생성 → 만료/취소 정상 동작(실제 입금 없이).
6. 출금 신청 1건 생성 → 잠금 포인트 증가 확인 → 반려 시 잠금 해제 확인.
7. `bunx vitest run`(게임 코어 + 카드 보안 회귀) 전체 통과.
8. 상점 구매 → 장착 → 게임방 반영 확인.

## 9. 금지 사항

- GAME CORE / GAME SECURITY 기준선 변경, 카드 raw 접근 재개방, `test_driver_enabled` 활성화.
- 충전 7% · 총판 2% · 출금 0% 정책 변경.
- 회원/포인트/충전/출금/상품/구매이력 데이터 삭제 또는 초기화.
- finding·로그 삭제(상태 전환만 허용).
